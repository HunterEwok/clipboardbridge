# 工作原理

本页用图示说明 Clipboard Bridge：群组里有哪些设备，它们在家里如何找到彼此，以及离家后有哪些方式保持联系。确切的规则见[设计文档](../design.md)；使用时并不需要了解它们。

## 群组

你的设备组成一个**群组**。只有你放行的设备才属于它，设备之间只与彼此通信，并且始终加密（TLS）。每台设备都有一个角色：

| 角色 | 是谁 | 做什么 |
|---|---|---|
| **根** | 创建群组的手机（[不使用应用](without-app.md)时是电脑） | 保管群组的密钥，添加和移除设备，指定管理员 |
| **管理员** | 第二部手机，或根指定的一台电脑 | 像根一样添加和移除设备 |
| **成员** | 每台电脑和每部手机 | 同步剪贴板 |
| **轻量成员** | 小型 Linux 设备：路由器、Raspberry Pi Zero | 只同步，不添加任何人（[轻量成员](../../lite/README.md)） |
| **无 root 成员** | 不使用 `sudo` 安装的 Linux 电脑 | 像成员一样同步，但永远不能成为根、管理员或中枢（[见下文](#rootless-members)） |
| **中枢** | 家中的管理员电脑，或者（如果你想要的话）应用开着时的手机 | 让你的设备在离家时也能同步 |

手机的密钥生成于它的安全芯片（Secure Enclave、Android 的 Keystore）中，永远不会离开芯片；每次使用都需要验证你的面容、指纹或密码。电脑则把密钥保存在只有 Clipboard Bridge 能读取的文件中。

### 无 root 成员

通常，安装程序需要用一次 `sudo`，这样 Clipboard Bridge 就能在它自己的账户下运行：你的浏览器、游戏和你运行的所有其他程序都读不到它的密钥，系统还会把这项服务限制在严格的沙箱里。无 root 安装则省去了这一步，适用于你没有 `sudo` 的电脑，比如工作用的电脑。它和其他成员一样同步，但你的任何程序都可以复制它的密钥并冒充它，所以即使你要求，它也永远不能成为根、管理员或中枢。设备列表会把它标为“rootless”。Steam Deck 不需要这种方式：它使用常规安装（[安装](install.md#steamos-steam-deck)）。

## 两种群组

群组可以以一台电脑为核心，也可以只由手机组成。两种方式都得到完整支持，你也可以随时从一种换到另一种。我们推荐使用一台经常开机的电脑，原因见表格下方。

| | 有电脑 | 只有手机 |
|---|---|---|
| 谁保管群组的密钥 | 手机（在其安全芯片中），或[不使用应用](without-app.md)时的电脑 | 手机，在其安全芯片中 |
| 在家同步 | 每台设备直接同步 | 每台设备直接同步 |
| 离家同步 | 随时通过作为中枢的电脑 | 应用开着时通过作为中枢的手机（Android 在后台也可以），或通过盲中继 |
| 你需要什么 | 一台经常开机的电脑 | 不需要别的 |

我们为什么推荐电脑：它开机的时间比手机上应用开着的时间长得多，而 iPhone 只给应用很少的后台运行时间，所以有了电脑，离家同步就能稳定工作。当一台始终开机的电脑加入由手机组成的群组时，手机应用会提议把它设为中枢。

## 在家：不需要中枢

在同一个家庭网络中，设备会通过 mDNS 自动找到彼此并直接连接。任何数据都不会离开你的网络，中间也没有服务器：任何设备都可以关机，其余设备照常同步。

![在家时，每台设备都直接与其他每台设备通信，没有服务器](../images/at-home.svg)

**家里有两个网络**，比如单独为智能设备设了一个网络：mDNS 不会穿过路由器，所以位于不同网络的设备无法自己找到彼此。手机应用会记住二维码中每台电脑的地址，因此仍能连上它；轻量成员可以被告知某台电脑的地址（[`-peer`](../../lite/README.md#install)）；其他情况则由中枢（见下文）把两边连起来。

## 离家：中枢

笔记本或手机离开家后，需要一条回家的路。家里的一台电脑成为群组的**中枢**：离家的设备通过群组自己的加密隧道（WireGuard）连接到它，再由它把剪贴板转发给家里的所有设备。

![离家时，笔记本和手机通过群组的 WireGuard 隧道连接到家里的中枢](../images/hub.svg)

- 中枢是你自己的电脑，而且必须是管理员：Linux、Windows、Mac、FreeBSD 或路由器。中枢是群组的完整成员：它和你的任何设备一样能读取剪贴板，所以它必须是你自己的。
- 你的路由器把一个 UDP 端口（8764）转发给中枢，互联网才能访问到它。
- 中枢不必一直开着。它关机时，离家的设备无法同步，而在家的设备不需要它也能照常同步。
- 设备在家时会获取中枢的信息，所以请在出门前开启离家同步。

设置方法见[离家使用](away-from-home.md)。

## 当互联网无法访问你的中枢时：转发器

许多运营商让家庭共用同一个地址（运营商级 NAT），这时端口转发也无济于事。中枢可以改为向**转发器**注册：转发器是互联网上的一台服务器，在你的设备和中枢之间传递隧道的加密数据包。中枢主动向转发器发起连接，所以家里不需要开放任何端口。

![位于运营商 NAT 之后的中枢主动连接转发器，转发器把离家设备的隧道转交给它](../images/forwarder.svg)

转发器不持有任何密钥，也读不到任何内容：它只能看到发往你的中枢的加密数据包。有两种：

- **你自己的**：在任何有公网地址的服务器上运行 `cbb forward`，比如一台便宜的虚拟服务器（[运行自己的服务器](../admin/self-hosting.md)）。
- **`cbb.tools` 上的 Clipboard Bridge 转发器**，由项目为所有人运行。它仍在测试中，尚未向所有人开放；开放时，它的地址和密钥会写在本页。

设备先尝试中枢自己的地址，最后才尝试转发器。

## 当网络封锁 WireGuard 时

有些网络（酒店、办公室、某些国家）会封锁 VPN 流量。中枢可以伪装群组的隧道：

- **混淆**（`-obfuscate`）：隧道使用 AmneziaWG，它在网络上看起来不像 WireGuard。电脑和两个手机应用都支持。
- **VLESS 与 REALITY**（`-vless`，通过转发器）：设备在看起来像是连接到某个知名网站的普通 HTTPS 连接中访问转发器。适用于以上两种都被封锁的网络。电脑和两个手机应用都支持。

轻量成员只支持普通的 WireGuard，所以使用这两种方式时，它只能在家同步。

## 只有手机：手机作为中枢

只由手机组成的群组，或由手机和 Mac 组成的群组，没有电脑可以当中枢。有两种方式可以让它离家时继续同步：

- **手机作为中枢**，在其应用打开期间有效（设置，**This phone as the hub**；在手机上创建的群组一开始就是开启的）。其他手机、电视和轻量成员在家时连接到它，有了转发器，在远处也能连上。Android 上它可以在后台持续运行；iPhone 只有在应用打开时才提供服务。
- **你自己的盲中继**（在你的服务器上运行 `cbb relay`）。它代替中枢充当会合点，但不是成员：设备间的加密是端到端的，穿过它而不被解开，所以它无法读取剪贴板。不过它能看到你的哪些设备在通信、何时通信。电脑和两个手机应用都可以使用它。

![盲中继连接离家的笔记本和在家的 Mac；加密端到端穿过它](../images/relay.svg)

一个群组可以有多个中枢：根和每个设置了中枢的管理员。离家的设备使用第一个应答的中枢，手机优先，所以由手机和电脑组成的群组在手机应用关闭时仍能工作。

**计划中：**在 `cbb.tools` 上提供一个盲中继，给不想运行中枢或中继的所有人使用。它会看到哪些设备在通信以及何时通信，但永远看不到复制的内容，并且需要你自己开启。

## 各种服务器能看到什么

| 服务器 | 读取剪贴板 | 知道你的哪些设备在通信，以及何时通信 | 属于谁 |
|---|---|---|---|
| 中枢 | 能，它是你自己的设备 | 知道 | 你自己的 |
| 转发器 | 不能 | 不知道：它只看到加密数据包的来源地址，以及发往你的中枢的数据 | 你自己的，或项目在 `cbb.tools` 上的 |
| 盲中继 | 不能 | 知道 | 你自己的（计划在 `cbb.tools` 上提供一个） |

不涉及任何其他东西：没有账户，没有云，没有遥测。其他所有能看到一点信息的方，从你的 Wi-Fi 到更新检查，都列在[隐私](privacy.md)中。开启离家同步后，电脑上的 Clipboard Bridge 服务只能访问家庭网络，以及群组自己的中枢、转发器和中继。
