# 密钥与证明

群组中的每台设备都有密钥：一把向其他设备证明自己的身份，而根和管理员的密钥负责添加和移除设备。设备把密钥存放在哪里，决定了小偷拿到设备后能得到什么。本页说明每种设备把密钥存放在哪里，群组如何检查，以及该选择哪个严格级别。确切的规则见[协议](../protocol.md)第 17 节。

## 密钥存放在哪里

| 位置 | 设备 | 小偷能得到什么 |
|---|---|---|
| **在文件中** | Mac 和 Windows 电脑、没有 TPM 的 Linux 电脑、轻量成员 | 文件的一份副本，在管理员移除该设备之前，它在任何地方都能使用 |
| **在硬件中** | iPhone（Secure Enclave）、Android 手机（Keystore：StrongBox 或 TEE）、带 TPM 的 Linux 电脑 | 没有可复制的东西：密钥只能在那台设备上签名，而在手机上，根和管理员的密钥只有在验证你的面容、指纹或密码之后才会签名 |
| **经证明的硬件** | 密钥已由群组的根检查过的 Android 手机 | 与硬件相同，而且群组知道这是真的，而不只是设备自己这么说 |

应用中的设备列表和 `cbb status`（KEYS 列）会显示每台设备属于哪一种。

## 密钥如何被证明

设备可以声称它的密钥在硬件中，但被修改过的程序也可以这么说。有些硬件能够证明这一点：

- **Android。**应用生成密钥时，手机的 Keystore 会签发一份描述该密钥的证书：密钥位于 StrongBox 或 TEE 中，手机的引导加载程序已锁定，系统经过验证。该证书一直链接到 Google 的证明根。应用把它发送给群组的根，根检查后将这部手机记为**已证明**。整个过程不会向 Google 发送任何东西。
- **引导加载程序已解锁的手机，或使用自有密钥签名系统的手机**（GrapheneOS 等）把密钥保存在硬件中，但检查无法为其周围的系统担保。它算作硬件，而不是已证明。
- **被吊销的手机。**Google 会公布一份证明密钥已泄露的手机名单。项目的服务器 `cbb.tools` 每天复制一次并为这份副本签名。群组的根获取这份副本，所以你的设备从不会去询问 Google。名单上的手机会从已证明降为硬件。
- **带 TPM 的 Linux 电脑**把成员密钥和管理员密钥保存在其中，所以这些密钥算作硬件。如果 TPM 的制造商把证书写进了芯片（英飞凌、ST 和新唐的芯片，如树莓派的 TPM 板），它就能向群组的根证明这一点，根随即将这台电脑记为**已证明**；不需要向制造商询问任何事。Intel 和 AMD 的固件 TPM 通常把证书放在制造商的服务器上，所以它们仍算硬件。**Apple 设备**（App Attest）目前还不能证明它们的密钥。

## 三个级别

你的群组有一个级别，它决定了在设备可以充当根、管理员或中枢之前，群组必须有多大把握。

1. **严格。**只有已证明的硬件才能成为根、管理员或中枢。为了证明更多设备，这个级别还会询问你家之外的服务：Apple（App Attest），以及 Intel 或 AMD（部分 TPM 证书）。这些服务会得知，有这类设备从你的地址发来了请求。Android 证书链只有经由 Google 的远程密钥配置（Remote Key Provisioning）时才被接受。
2. **硬件（默认，推荐）。**密钥在硬件中的设备可以成为根、管理员或中枢，无论是否已证明。不需要外部服务的证明（Android、证书在芯片上的 TPM）仍会被检查并显示。除了从 `cbb.tools` 获取吊销名单副本（对所有人都是同一个文件）之外，你的设备没有任何信息离开你家。
3. **允许文件（最不安全）。**密钥在文件中的设备在收到警告之后，也可以成为管理员：任何复制了该文件的人，在另一位管理员移除该设备之前，都能以管理员身份行事。密钥不在 TPM 或 Secure Enclave 中的电脑，只能通过这种方式成为管理员（`cbb admin -allow-file-key`，或手机上“Make it an admin”对话框中的警告）。

默认使用级别 2，是因为它在硬件允许的情况下让密钥远离文件，同时不必告诉任何外部服务你有哪些设备。

不使用 `sudo` 安装的电脑（[无 root](install.md#without-sudo-rootless)）在任何级别下都不能成为根、管理员或中枢：其用户的每个程序都能读取它的密钥。

## 如果设备丢失

请尽快把它从群组中移除：见[设备丢失或被盗时](lost-device.md)。硬件中的密钥离开设备就无法使用；文件中的密钥则在设备被移除之前一直可以使用。

## 尚未实现的部分

以上级别是设计；当前版本只实现了其中一部分：

- Android 手机会证明它们的密钥，根会检查证明和 Google 的名单。`cbb.tools` 上的副本要等项目的签名密钥建立之后才会开始提供。
- 这些级别目前还不是设置项。群组按级别 2 运作，而电脑只有通过级别 3 的警告才能成为管理员，带 TPM 的 Linux 电脑除外。
- 带 TPM 的 Linux 电脑从加入群组的那一刻起，就把成员密钥和管理员密钥保存在其中；更早加入的电脑在重新加入之前仍使用文件。电脑上的群组根密钥、Mac（Secure Enclave）、Windows 电脑（TPM）以及 App Attest 尚未实现：在此之前，它们的密钥都在文件中。
