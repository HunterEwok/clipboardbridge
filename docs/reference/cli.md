# Command reference

Every command of `cbb`, on a full member (Linux, macOS, Windows) and on the lite member, with
their flags and environment variables. `cbb help` prints the short form of the one installed;
`cbb version` says which it is.
Commands other than `service`, `agent`, `version` and `help` talk to the running
service. `copy`, `paste`, `status` and `agent` use the control socket, which members of the
`clipboardbridge` group (`_clipboardbridge` on macOS) reach without `sudo`. Every command
that changes the group or this device's place in it (`new`, `pair`, `invite`, `revoke`,
`rename`, `admin`, `takeover`, `upgrade`, `freeze`, `unfreeze`, `holder` with a setting,
`global on|off|hub|...`, and on the lite member `global on|off`) uses the admin socket, which
only root reaches: run it with `sudo`, on Windows from a terminal opened as administrator.

## cbb

| Command | What it does |
|---|---|
| `cbb copy [-secret]` | Sends standard input to the group, and to this device's own clipboard. `-secret` sends it as a secret: kept only in memory and gone 60 seconds after the copy. |
| `cbb paste [-terminal [-lines] [-secret]]` | Prints this device's clipboard text; in the sync modes `own` and `send`, which keep the group's copies out of the clipboard, the group's latest text. `-terminal` makes it safe to paste into a terminal, as tmux's paste key does: it drops the control characters (C0 but tab and line feed, DEL, C1), keeps only the first line unless `-lines`, leaves out the last line feed, and refuses a secret unless `-secret`. |
| `cbb mode [own\|shared\|receive\|send]` | Shows or sets this device's sync mode, what moves between its clipboard and the group; set it with `sudo` on Linux and macOS, as administrator on Windows. `own`, a new device's mode, keeps the clipboard to itself: copies here stay here, the group's do not come, and `cbb paste` prints the group's text instead. `shared` sends copies to the group and takes the group's; `receive` only takes them, `send` only sends. `cbb copy` and the phones send to the group in every mode. A device that joined its group before 0.5 stays `shared`. |
| `cbb mode -on DEVICE own\|shared\|receive\|send` | On an admin: sets the sync mode of another device of the group (its name or device ID) with a signed command, which the device takes only while it is connected to this one; run it with `sudo` or as administrator. Phones and the lite member take it too. |
| `cbb status` | This device, its sync mode, its group, sync away from home, and every device of the group: its system (Linux, Windows, macOS, iOS, Android), its role (`full`, `lite`, `phone`, `shortcut`), whether it is the root or an admin, when it was last seen and whether its clock is off. It also says whether this computer answers for `clipboardbridge.local`, and warns when members at home could not connect to this computer and sync only because it dials them back, as when a firewall here drops the member port. |
| `cbb rename NAME NEW-NAME` | Gives a device of the group, by name or device ID, another name (1 to 64 characters): an admin signs a new device record with it, and every device and app shows it once it hears of it. Runs on an admin, which renames any device, itself and the root included; the phones' Devices list does the same. |
| `cbb revoke NAME` | Removes a device, by name or device ID, with a signed record; the group stays. Runs on an admin: the computer that created the group (its root), a computer the root made an admin (`cbb admin`), or a computer the root phone made an admin. Only the root (or an admin phone) removes an admin: an admin computer's key sits in a file, so it removes ordinary devices only. Removing an admin of a computer's group also replaces the iPhone CA, so iPhones that use the shortcut pair again. The root is removed with `cbb takeover`. In a phone's group, remove devices in the app (Devices). |
| `cbb freeze NAME` | Freezes the admin computer NAME, as one that was stolen, on any admin: from then on nothing it signs counts beyond the records it signed before, which stay, and the members refuse its connections. It cannot freeze the root or an admin phone. A frozen admin may freeze back; both then stay frozen until the root decides. |
| `cbb unfreeze NAME` | On the group's root: ends every freeze of the admin computer NAME, which is an admin again. In a phone's group, use "Unfreeze" on the root phone or an admin phone; `cbb revoke` on the root (or Remove on a phone) removes it for good. |
| `cbb admin NAME` | On the group's root: makes the computer NAME (a name or a device ID) an admin, which can then admit and remove devices and serve the shortcut. It must be connected. In a phone's group, use "Make it an admin" on the root phone. |
| `cbb install [options]` | Windows: installs the service, the agent and the firewall rules from the copy of `cbb` that winget unpacked, by running `packaging\windows\install.ps1` beside it in an administrator terminal; the options are the installer's (`-Express`, `-Port N`, `-HomeCgnat on`). Run it again after `winget upgrade`. |
| `cbb upgrade` | Once, on a Linux or Windows member of a group made before 0.4, after every member runs this version: the group gets a root, this computer, and only it and the admins it makes hold keys from then on. The others delete their copies of the old keys when they hear of it; `cbb status` marks those that have not yet, and they cannot be removed until they have. The iPhone CA is replaced, so iPhones that use the shortcut pair again. No device pairs again. |
| `cbb takeover NAME` | On an admin, when the root computer NAME is lost: this computer becomes the group's root and NAME is removed. The devices stay in the group; the iPhone CA is replaced, so iPhones that use the shortcut pair again. In a phone's group an admin phone takes over instead. |
| `cbb new` | Creates a group with this computer as its root: it holds the group's root key and the iPhone CA, admits devices and makes admins. A computer in a group already keeps it. |
| `cbb pair` | Does what this computer's place calls for. In a group, on the root or an admin: admits a new computer, showing a six-digit code to type there, and waits. In no group: joins one, showing a QR code for the phone app and taking the code of `cbb pair` on the group's root or an admin, typed meanwhile. On a member that is neither, it names the devices that admit. |
| `cbb pair -code [ADDRESS]` | Joins with the code from `cbb pair` on the group's root or an admin, read from the terminal or standard input (never from the command line, where other users could read it). Without an address it finds that computer on the home network; with one (`host:port`) it dials it, for example through an SSH tunnel or your own VPN (see [Without the app](../guide/without-app.md#joining-from-another-network)). |
| `cbb pair -phone` | Pairs an iPhone or iPad with the shortcut: shows a QR code, the start of the iPhone CA's fingerprint and a code. Run it on the root or an admin that answers for `clipboardbridge.local`, after `cbb new`. The shortcut's token only syncs. |
| `cbb pair -phone -new-token` | Revokes the token of every shortcut paired so far, then pairs this iPhone as `cbb pair -phone` does, with a new token. Use it when a token may have been copied; the other iPhones pair again. |
| `cbb pair -invite FILE` | Joins from afar with an invitation file from `cbb invite`, through the hub's guest tunnel. It runs with `sudo` on Linux and as administrator on Windows, as `cbb global on` does: the service may reach the hub's addresses from the invitation, and a failed join takes them away again. Both sides show the new device's key fingerprint; the hub admits it once its admin types `yes`. |
| `cbb invite [-for DURATION] [-o FILE]` | Runs on the group's hub, with sync away from home on: writes an invitation for a device away from home (default `clipboardbridge.cbbinvite`, valid for 1h, at most 24h) and waits to confirm it. The file is a secret until it is used; copy it through a channel you trust. |
| `cbb global` | Shows sync away from home on this device: on or off, the hub, the tunnel, and what went wrong. |
| `cbb global on` | Turns sync away from home on here, after a warning about where the keys are kept. On Linux it runs with `sudo`, on Windows in a terminal opened as administrator: the service may reach only the home network, and it lets it reach the group's own servers (hub, forwarder, relay) as well, and nothing else on the internet: a systemd drop-in with their addresses on Linux (the service restarts), the outbound rule `clipboardbridge-home-only` of Windows Firewall without them; on a Mac only the service's own limit follows, and `sudo` is not needed. A client waits a few seconds for its hub's offer, which names the hub's addresses. |
| `cbb global allow` | Lets the service reach the group's servers as it knows them now, run as `cbb global on` is: after the hub's addresses changed or first became known, when `cbb global` or `cbb status` says the system's limit lags behind. With sync away from home off or in no group it takes back what the limit allowed. The installers run it after an update, so a limit an earlier version left (on Linux, a drop-in that allowed every address) follows the current state. |
| `cbb global off` | Turns it off and forgets the tunnel keys. Run as `cbb global on` is, it also takes the group's servers out of the limit, so the service may again reach only the home network. |
| `cbb global hub [-port N] [-firewall ask\|yes\|no] [-obfuscate] [-forwarder ADDRESS:PORT -forwarder-key KEY [-vless]] [ADDRESS:PORT...]` | The forwarder may be given by name (`cbb.tools:8764`); the command looks the name up once and the hub keeps the address. Makes this device the group's hub, reached from the internet at these addresses, through a forwarder, or both; `-port` sets the UDP port the tunnel listens on. With `-forwarder` the hub registers with that forwarder, whose key `-forwarder-key` pins, and its clients try it after the hub's own addresses. `-obfuscate` makes the tunnel speak AmneziaWG, for networks that block WireGuard: the hub makes the group's settings once and keeps them while `-obfuscate` stays, and its clients get them at home with its offer; with a forwarder, the hub gives it the settings. `-vless` has the clients reach the forwarder only inside VLESS with REALITY, which looks like HTTPS to a well-known site, for networks that block WireGuard and AmneziaWG alike; the forwarder must run with `-vless-site`. A hub reached at its own address lists the firewall rule its UDP port needs (from any address, since its clients are on the internet) and asks before it adds it, as the installers do; `-firewall yes` adds it without asking, `-firewall no` prints the commands. cbb closes the port again when this device stops being a hub reached at its own address (another port, only a forwarder, `cbb global off`). A router in front of it must forward the port too. The hub need not stay on: while it is off nothing syncs away from home, and at home the devices sync without it. |
| `cbb global relay ADDRESS:PORT -key KEY [-yes]` | The relay may be given by name, looked up once. For a group without a hub: this device meets the group's other devices away from home at the blind relay at that address, whose key `-key` pins. It first says what the relay learns (which devices are online and from where, which talk, when and how much) and asks you to type yes; `-yes` agrees without asking, for scripts. It registers there with its member certificate, and the relay joins its member connections to the others' end to end. It replaces the hub and the hub's offer on this device. |
| `cbb forward [-listen ADDRESS:PORT] [-key FILE] [-records DIR] [-show-key] [-vless-site NAME [-vless-listen ADDRESS:PORT]]` | Runs a forwarder on a server with a public address, for hubs that clients cannot reach directly, for example behind carrier-grade NAT (default port 8764, UDP and TCP). It holds no keys of any group; of each group that registers it writes only the records that are no device records (the group's roots, removals and freezes, never a device's name), so that a device the group removed cannot register later with older ones, in `-records` (default `groups` next to the key; `none` keeps them in memory only). Its own key is made in `-key` on the first run (default `forwarder.pem` in systemd's state directory, or in the service's state directory) and printed at start, or alone with `-show-key`. With `-vless-site`, it also takes VLESS with REALITY on TCP `-vless-listen` (default `:443`) for the clients of hubs that ask for it, borrowing the TLS of that well-known site (such as `www.example.com`), whose own answers whoever is not a client gets; its REALITY key is kept in the same key file. |
| `cbb relay -group TAG[,TAG...] \| -open [-listen ADDRESS:PORT] [-key FILE] [-show-key]` | Runs a blind relay on a server you run, for groups that have no computer to be the hub (default port 8764, UDP and TCP). It serves only the groups whose tags `-group` lists (`cbb status` shows a group's tag), or with `-open` every group that registers, within limits per group and per network, holds none of their keys, reads nothing of the clipboard, and writes nothing about them; it sees which devices of a group talk, when and how much. Its keys are made in `-key` on the first run (default `relay.pem` in systemd's state directory, or in the service's state directory), and the key to give `cbb global relay -key` is printed at start, or alone with `-show-key`. |
| `cbb version` | Prints the version and the platform. |

### Rarely needed

`holder` only matters when the wrong computer answers to `clipboardbridge.local`. The system
starts `service` and `agent`; they are run by hand only to look into a problem, such as to
see the agent's log in a terminal.

| Command | What it does |
|---|---|
| `cbb holder [auto\|first\|fallback\|never]` | Shows or sets whether this computer holds `clipboardbridge.local`, the name the iPhone shortcut reaches: `first`, only as a `fallback` when no computer set first is on, or `never`. `auto`, the default, picks `fallback` on a machine with a battery and `first` on any other. Only a computer with the group's iPhone key takes part. |
| `cbb network` (with sudo) | Takes the networks this computer is on now as networks where its group is. A computer publishes itself and takes connections only on those (design.md, "Known networks"); it learns them by itself when it creates or joins the group, opens a pairing window or connects to a member there. Needed only at home after a new router, when every member keeps quiet; `cbb status` says "Quiet on" for such a network. |
| `cbb service` | Runs the service; started by systemd, launchd or the Windows service manager, not by hand. |
| `cbb agent` | Links this desktop's clipboard to the service: the Mac's pasteboard, the Windows clipboard, or a Linux desktop's through Wayland or X11. It starts by itself at sign-in (`cbbw.exe agent` on Windows, the autostart entry on a Linux desktop); run it by hand only to see its log. |

## The lite member

On a small Linux device `cbb` is the lite member, with the same paths and service as a full
member (`/var/lib/clipboardbridge`, `clipboardbridge.service`) and the commands below; the
commands of a full member, such as `pair` or `invite`, answer that this is the lite member.
Global flags, before the command: `-state DIR` (default `/var/lib/clipboardbridge`, or
`CBB_STATE`), `-socket PATH` (default `/run/clipboardbridge/control.sock`, or `CBB_SOCKET`),
`-debug` (the details of errors). Install and use are in [lite/README.md](../../lite/README.md).

| Command | What it does |
|---|---|
| `cbb join [-name NAME] [-port PORT] [-addr HOST[:PORT]]...` | Joins a group by QR code, scanned by the phone app or the shortcut. `-addr` names where the phone reaches this device, when the QR code would name the wrong addresses. |
| `cbb join -code HOST:PORT` | Joins with the code from `cbb pair` on the group's root or an admin. |
| `cbb run [-name NAME] [-port PORT] [-peer HOST:PORT]... [-no-mdns] [-no-listen]` | Runs the service (systemd or procd). `-peer` names a full member on the home network to dial, for networks without mDNS; `-no-mdns` turns mDNS off; `-no-listen` closes the member port, so the device only dials. |
| `cbb global [on\|off]` | Shows sync away from home, or turns it on (after the warning about keys in files, typing yes) or off here. Once on, the device meets the group's hub at home, keeps its offer, and away from home reaches it through the group's WireGuard tunnel; a hub that hides its tunnel (`-obfuscate`, `-vless`) keeps the lite member at home. |
| `cbb copy [-secret]` | Sends standard input to the group. |
| `cbb paste [-terminal [-lines] [-secret]]` | Prints this member's clipboard text, or the group's text in a sync mode that does not receive; `-terminal` as on a full member. |
| `cbb mode [own\|shared\|receive\|send]` | Shows or sets the sync mode, as on a full member; setting it needs `sudo`. A lite member that joins starts in own. |
| `cbb status` | This device, its sync mode, its group, and every device of the group with its system, role and marks. |
| `cbb watch [-0]` | Prints each text the group sends here, one per line, or followed by a zero byte with `-0`. |
| `cbb next paste [-max BYTES]`, `next copy LEN CRC32`, `next join [-name NAME] [-port PORT] [-addr HOST[:PORT]]...` | The same for the ZX Spectrum Next's `.cbb` dot command, in frames its Z80 reads; see [lite/README.md](../../lite/README.md#zx-spectrum-next). |
| `cbb version`, `cbb help` | The version and that this is the lite member; this help. |

## Installers

| Installer | Options |
|---|---|
| `get.sh` (Linux and macOS) | Downloads this system's archive, checks it against `SHA256SUMS` and runs its `install.sh`. `--express` adds the firewall rules without asking, `--no-firewall` adds none, `--port N` sets another member port, as for `install.sh`; on Linux also `--console` and `--lite` for the lite member instead of the full one. With the one-line installer, put them after `sh -s --`. `CBB_VERSION=v1.2.3` installs that release. Running it again updates. |
| Linux `install.sh` (the same in the full and the lite member's archive) | Finds the firewall (ufw, firewalld, nftables, iptables), lists the rules Clipboard Bridge needs and asks `Add these rules now? [y/N]`; the answer is kept in `/etc/clipboardbridge/firewall.answer` for later runs. `--express` adds them without asking and reports them, `--no-firewall` adds none and prints the commands that would; nftables and iptables always get the commands. `--port N` another member port (kept for later runs; `--port 8764` goes back), `--console` also starts tmux on the text console. |
| Linux `uninstall.sh` (`/usr/local/share/clipboardbridge/`) | removes the program, the service and the firewall rules the installer added; `--purge` also deletes the keys in `/var/lib/clipboardbridge`. |
| macOS `install.sh` (in the release archive's `packaging/macos`, or under `$(brew --prefix)/opt/clipboardbridge/share/clipboardbridge`) | `--port N` another member port (kept for later runs; `--port 8764` goes back), `--in-place` has the agent and `cbb` in PATH run the binary where it is (Homebrew) instead of copying it, while the service runs a root-owned copy under `/Library/Application Support/clipboardbridge/bin`; it asks before it lists the service in the application firewall, and `--express` and `--no-firewall` work as on Linux. |
| macOS `uninstall.sh` (`/usr/local/share/clipboardbridge/`) | removes the service, the agent and the program; `--purge` also deletes the keys. Before `brew uninstall`. |
| Windows `get.ps1` and `install.ps1` | Lists the Windows Firewall rules Clipboard Bridge needs and asks before it adds them; the answer is kept for later runs. `$env:CBB_PORT = "9000"` (or `-Port`) another port, `$env:CBB_FIREWALL = "express"` (or `-Express`) adds the rules without asking, `$env:CBB_FIREWALL = "no"` (or `-NoFirewall`) adds none and prints the commands. The outbound rule that keeps the service at home is added either way. |
| Windows `uninstall.ps1` (`$env:ProgramFiles\clipboardbridge`), or Settings, Apps | removes the service, the agent, the program and the firewall rules; `-Purge` also deletes the keys and the `clipboardbridge` group. |

## Environment variables

| Variable | Used by | Meaning |
|---|---|---|
| `CBB_DEBUG` | `cbb` | `1` shows the underlying error under each message; `0` hides it in a development build, which shows it by default. The service's log always has the details. In the service's environment, also WireGuard's own messages for sync away from home. |
| `CBB_PORT` | the service, the lite member's `cbb run` | The member port, 8764 by default. The installers keep it: `/etc/clipboardbridge/clipboardbridge.env` on Linux and macOS, the service's registry key on Windows; change it by running the installer with `--port N` or `$env:CBB_PORT`. |
| `CBB_HOME_CGNAT` | the service, the installers | `1` counts 100.64.0.0/10, the carrier-grade NAT range, as the home network too, for a home network that uses it: the service accepts and reaches it, publishes its addresses there, and the installers open it in the firewall and in the system's outbound limit (the systemd drop-in `cgnat.conf` on Linux, the Windows rule). Unset or `0`, it is outside the home network. Set it with `--home-cgnat on` (`off` goes back), `-HomeCgnat on` on Windows, or this variable for the installers; they keep it beside `CBB_PORT`. |
| `CBB_SOCKET` | `cbb` | Another control socket, for tests or a second instance. |
| `CBB_STATE` | the lite member | Another state directory. |
| `CBB_FIREWALL` | `get.sh`, Linux and macOS `install.sh`, Windows `install.ps1`/`get.ps1` | `express` adds the firewall rules without asking (`--express`), `no` adds none and prints the commands (`--no-firewall`); unset, the installer asks. |
| `CBB_VERSION` | `get.sh` | A release such as `v0.2.0` instead of the latest. |
| `CBB_ERROR_DETAILS` | the installers: Linux and macOS `install.sh`, `uninstall.sh` and `get.sh`, Windows `install.ps1` | `1` shows every command the shell scripts run, so the output shows where and why one failed, and adds the full error record to the Windows installer's messages. Without it a failed shell script names its exit status. |

The test-only variables (`CBB_INTEROP_OUT`, `CBB_LITE`, `CBB_SWIFT_INTEROP`, …) are in
[CONTRIBUTING.md](../../CONTRIBUTING.md).
